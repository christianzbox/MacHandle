# PR-01 — Repository Foundation and Security

## Objective
Establish a buildable, reviewable native skeleton and safe public-repository workflow.

## Prerequisites
Existing `christianzbox/MacHandle` main initialization (`2429cc2`). Preserve repo
identity, public visibility, Apache-2.0 license, and existing protections.

## Context
Read AGENTS, current state, architecture, ADR-0001, and master specification
sections 13–18, 20–23, 27. This PR deliberately contains no service implementation.

## In Scope
Minimal Xcode/SwiftPM skeleton; exact supplied master specification; roadmap and
initial briefs; security/privacy/contribution/release docs; synthetic test harness;
ignore rules; CI; pinned secret scanning; indexed-file privacy checks; GitHub PR.
Additional user requirement: interchangeable work/home Mac development, exact
shared toolchain, independent clone/build/test setup, portable Codex guidance,
and GitHub-backed unfinished-branch/PR handoff.

## Out of Scope
Apple permissions/provider access, Google OAuth, sync, MCP, Reminders, Contacts,
Notes, product UI beyond a development window, release signing/distribution.

## Contracts
No personal data or secrets in Git. No network or data access from the app.
No implementation claimed from planning documents. Preserve existing initialization.

## Security
Read-only CI token, no persisted checkout credentials, immutable action pin,
checksum-pinned scanner, synthetic fixtures. Manually review the full staged diff.
Preserve main rules and add required checks only after observing their actual names.

## Implementation Notes
Use native SwiftUI and SwiftPM without third-party runtime packages. Record actual
local Xcode/SDK/compiler and differences from hosted tools. Preserve master bytes.

## Tests
Both Scripts/validate.sh and Scripts/scan_secrets.sh; source and license integrity;
verify hosted checks independently. Test preflight drift/custom-path failure modes
and a fresh checkout in a path with spaces. No service or production claims.

## Acceptance Criteria
Skeleton builds, synthetic tests pass, privacy/secret checks pass, documentation
supports a fresh session on either Mac without prior chat history; the baseline
is explicit and checked; an unfinished branch can be resumed through GitHub.
PR targets existing main and stays open for review.

## Documentation
All initial docs; record PR URL, CI evidence, limitations, and next eligible brief.

## Handoff
Stop after opening PR-01. User reviews/merges. PR-02 starts in a fresh session only
after verified merge. No data integration exists yet.
