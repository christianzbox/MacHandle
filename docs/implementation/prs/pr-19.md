Implement trusted local connection identity/pairing, configuration and policy persistence,
revocation/session invalidation, unauthorized peer rejection and bounded content-free audit
metadata. Connections start disabled; pairing does not imply all Calendar grants. Bind each
read adapter to independently verified identity and selected resources. Caller metadata,
connection names, opaque read handles, process presence and arbitrary IDs cannot establish
identity or grant access. Credentials belong in Keychain, never arguments/environment/files.

First reconcile the signed external-helper-to-broker acceptance with actual development
identity availability. The maintainer has not supplied an approved signing team/registered
identity; do not invent one or weaken sandbox/peer requirements. Build/test independent
contracts with synthetic peers where possible, while keeping live external composition
closed until signed mutual authentication, channel binding and current OS invalidation
are exercised. Retain an explicit owner/revisit trigger for any unresolved runtime gate.

Test impersonation, disabled/unknown/revoked clients, replay/cross-channel identity reuse,
policy changes during reads, restart/persistence failure and redacted audit metadata. Keep
Google independent, no source mutations or write approvals. Review protocol/client versions
and align current per-request semantics with trusted identity; do not import legacy handshake
assumptions as authentication. Update ADRs, brief/roadmap/progress/coordination, prepare the
package 20 brief, run all three gates, push and open one review PR. Stop before merge,
public release or implementing package 20.

## Implementation and acceptance

| Requirement | Implementation / scoped evidence |
| --- | --- |
| Local identity and unauthorized peers | Default-deny channel verifier, rechecked at approval; synthetic rejection/race tests. Real signed verifier remains gated below. |
| Pairing/configuration | Opaque issuer/channel-bound single-use review, 60-second lifetime, revision and OS checks; labels and caller IDs cannot confer authority. Trusted API only, no native review UI yet. |
| Permission persistence | Validated private atomic candidate document; restores no enabled/session/credential state. Lock, permission, corruption, restart and failed-save tests. SQLite alternative in ADR-0024. |
| Revocation/session invalidation | Close admission before persistence, cancel owned reads, revoke policy, revalidate prepared output; replacement/EOF/OS/shutdown and uncooperative-provider tests. |
| Selected policy and independent use | Narrow read lease supplies bound session and selection; empty and same-name independent grants tested. No Google dependency or mutations. |
| Audit and resource bounds | 256 content-free entries, bounded pending/channels/read slots; cancelled providers retain shared capacity until completion. |
