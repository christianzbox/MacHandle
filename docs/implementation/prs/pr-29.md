Audit implemented paths first; use the relevant repository audit-planning skill. Build a bounded
inventory of actual connection state, sync diagnostics, local audit/history, error recovery,
accessibility and resource usage. Distinguish sample history, durable operation journals and genuine
provider activity. Remove misleading UI claims without implying that pending live integrations work.

Implement coherent diagnostics and recovery UX for current capabilities, including a strictly
allowlisted, content-free support export if safe to deliver. Exclude tokens, arbitrary errors/paths,
resource names/IDs, selections, payloads and private database contents. Use synthetic fixtures for
export/redaction failure tests and security review; manual review is still required. Audit relevant
permissions, local connection/approval/revocation, IPC/transport boundaries, persistence, uncertainty
and startup/lifecycle paths. Fix verified findings within this package and record unresolved findings
with severity, owner and revisit trigger; no broad rewrite or invented security certification.

Perform meaningful accessibility/keyboard/layout and scoped resource-usage checks without enabling
providers or requesting permissions. Do not inspect personal iCloud, TCC databases, credentials or
real client configurations. Signed/native/provider gates, Notes G1–G6 and remote R1–R6 stay closed.
Unimplemented features should have honest unavailability rather than fake success or recovery actions.

Acceptance: evidence-backed audit findings and fixes; diagnostics/export disclose only allowed
metadata; recovery respects unknown outcomes and never silently retries a mutation; native controls
are accessible for the verified scope; resource/OS/test limitations are explicit. Record decisions,
update roadmap/progress/coordination/brief/architecture, prepare package 30, run all three repository
gates, commit/push/open one PR and stop. No merge, auto-merge, publication, deployment or package 30.
