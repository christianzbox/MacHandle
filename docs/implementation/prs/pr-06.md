## Scope and boundaries

Implement supported EventKit calendar authorization and discovery behind explicit
application/provider dependencies. No request at app launch: explain the OS grant
and request only from a deliberate local Calendar opt-in. Keep not-determined,
denied/restricted, unavailable, write-only and full-access observations distinct.
Read access requires full access on the selected macOS floor; it does not grant
application write authority. Add only justified entitlement/usage-description changes.

Expose discovered accounts/calendars and explicit selection with device/store/account
identity from CoreDomain. Empty selection grants nothing; revoked access or missing
calendars clears/invalidates affected capability and stale displayed data. Refresh
current authorization and store observations at appropriate lifecycle boundaries.
Do not treat unavailable or partial discovery as an authoritative empty account.

Separate real OS observations from work package 05's synthetic preview authorities;
never promote a simulated full-access state to live authority. Views remain free of
EventKit and PolicyAuthority handles. Keep Google and MCP disabled and independent.
Record selection lifetime explicitly; do not silently add a second persistence system
before the package 10 storage decision. Do not log/export real calendar metadata.

## Exclusions and acceptance

No event reads/availability (package 07), source writes, Google/OAuth, MCP, Keychain,
sync scheduling, approval issuer or automatic login registration.

Synthetic provider tests must cover no eager request, opt-in sequencing, denial,
write-only versus full access, unavailable/partial discovery, source identity,
selection removal and authorization revocation. Keep domain dependency guards intact.
Run the three staged standard gates. Live TCC/sandbox discovery needs an explicitly
authorized isolated test account/device and separately reported evidence; never infer
live success from an injected fake or build. Home-Mac/oldest-OS coverage stays explicit.

Update the brief, roadmap, progress, coordination and provider/privacy ADRs with
actual contracts, alternatives, unresolved decisions and evidence. Prepare package 07's
brief; push one descriptively named review PR and stop without merging or proceeding.

## Implementation and acceptance

[ADR-0011](../../architecture/decisions/0011-calendar-authorization-discovery.md)
records design alternatives, race handling and data/verification boundaries.

| Requirement | Implementation / scoped evidence |
| --- | --- |
| Permission prompts only on opt-in | Lazy EventKit actor; explicit Enable; lifecycle refresh never requests; no eager-call and refusal tests |
| OS status distinctions | Mapping test covers not-determined/denied/restricted/write-only/full; unknown fails closed; write-only never enumerates a virtual calendar |
| Source identification | Provider/store/source/calendar IDs; validated coherent catalog rejects duplicate or foreign identities; names never determine equality |
| Calendar selection | Empty by default; only current exact IDs accepted; selections shrink on removal and clear on uncertainty/revocation/disable; observable checkbox/count regression |
| Denied/unavailable/partial | Separate UI states; coherent local-empty means only none returned locally, never remote completeness |
| Async safety | Disable during status/request/read, cancellation and concurrent refresh tests prevent late results from repopulating names/grants |
| Lifecycle | Window/foreground/store-change refresh while enabled; bounded Void notification stream and cleanup; no polling daemon |
| Native presentation | Real app off-state and Cmd-5 inspected; disposable synthetic native harness verifies selection/count, disable clearing, denied/incomplete/unavailable/local-empty rendering |
| Privacy/configuration | Calendar-only entitlement and usage description verified in built signed bundle; metadata/selection memory-only; no events, writes, credentials, external connections or logs |
| Standard gates | 65 Swift + 13 Python tests; exact staged/final-head checks recorded in progress and the GitHub PR |

Live TCC grant/deny/revoke and sandbox discovery require an authorized isolated test
account/device and remain unverified. The scoped implementation is reviewable without
accessing personal calendars; it is not a live-integration acceptance claim. Maintainer
and package 06/07 provider work own that runtime gate. Home/oldest-OS/release gates
remain explicit in ADR-0011. Package 07 now extends this merged work; see its [acceptance map](pr-07.md#implementation-and-acceptance).
