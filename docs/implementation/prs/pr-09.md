## Scope and trust boundary

Build the narrowly scoped Google destination client: create/read an app-created
secondary calendar, prove destination ownership, event CRUD primitives, bounded
pagination, rate-limit handling and sanitized errors. Never select `primary`, recover
by calendar title, enumerate unrelated calendars or widen OAuth scope silently.
Package 08 exposes no tokens to views; introduce a narrow trusted authenticated-client
boundary with refresh coalescing, current local authorization and disconnect fences.
Never expose raw token storage to transport clients or preview policy.

Use opaque destination ownership and observed versions. Update/delete require If-Match;
412 means refetch/replan. Unknown insert outcomes require a stable operation/event ID
and verification, not an unconditional new ID/retry. Do not implement the planner,
executor, persistent mapping database, source writes or MCP in this package.

The app-created scope cannot inspect ACLs. A calendar name or event visibility does
not prove privacy. Record a supported account-specific privacy verification flow or
keep source transfer blocked. Destination API primitives do not authorize sync or
remote cleanup. Coordinate durable lost-ID/ownership recovery with packages 10/14.

## Implementation and acceptance

[ADR-0014](../../architecture/decisions/0014-google-destination-client.md) records the
method audit, decisions/alternatives, limits and deferrals. The destination client
stays internal to GoogleAuthorization: no public activation factory or app wiring.

| Requirement | Implementation | Evidence / limit |
| --- | --- | --- |
| Narrow authenticated client | Fixed API origin, private bearer attachment, session leases, shared refresh and disconnect fences | Synthetic real-auth adapter tests; no live service or credential |
| App-created destination | Create response mints local handle; exact ID/marker/session rechecks | Foreign handle, marker mismatch, alias and encoded-path tests; not ACL proof |
| Event CRUD | Whitelisted payloads, stable insert plans, opaque observed ETags and If-Match | Create/read/update/delete fixtures, detail removal, guest/ownership rejection, conflicts |
| Unknown outcomes | No repeated insert; explicit same-ID/content verification; one attempted calendar create | Lost response, collision, not-found and changed-content tests; crash persistence deferred to 10/14 |
| Pagination | Complete-or-error, empty-page continuation, repeated-token/size/page limits | Synthetic multi-page, partial failure, cycle and oversized responses; not atomic snapshot |
| Rate limits/errors | Three bounded attempts, jitter, conservative Retry-After; no automatic 5xx write replay | Quota/ordinary 403, 429, 5xx, cancellation and limit fixtures |
| Privacy/activation | No source-reader dependency, no exported client, unchanged app/network capabilities | Two new compile-fail probes; account-specific privacy and signed acceptance remain blocked |
