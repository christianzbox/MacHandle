Implement incomplete-source and mass-deletion safeguards, destination reconstruction,
missing mapping recovery, source account/calendar migration, one-active-writer and
standby-device behavior. Every deletion already requires trusted exact confirmation;
preserve that invariant and distinguish explicit cancellation from missing/horizon state.
A successful local enumeration is still local-cache freshness, not upstream absence proof.

Resolve whole-process owned-destination restoration, prepared intent, lost calendar-creation
responses and missing/corrupt local state without trusting a remote title/marker alone,
blindly replaying unknown writes or inventing replacement IDs. Calendar/store/item changes
require verified continuity or intervention; never match by content/current start alone.
Content-v2 excludes timezone metadata while occurrence/calendar identity remains v1.
Old content-v1 baselines deliberately conflict: design verified rebaseline/recovery rather
than silently adopting hashes, deleting the database or recreating remote events.

A local file lock and executor busy flag do not coordinate multiple Macs. Establish and
test a destination writer/standby/transfer strategy, with safe denial when ownership cannot
be proven. Keep unresolved provider/auth/privacy/signing gates explicit and fail closed.
Use synthetic failure injection for missing/partial/revoked sources, crashes/unknown
results, stale writers, altered ownership, legacy fingerprints and account migration.
Do not activate real accounts or original-calendar writes to make the tests pass.

Update brief/roadmap/progress/coordination and affected ADRs with alternatives, tradeoffs,
owners/triggers and exact evidence. Run all three staged repository gates, prepare package
15's brief and open one review PR. Stop before merge or the next work package.

## Implementation and acceptance

[ADR-0019](../../architecture/decisions/0019-deletion-safety-recovery.md) records decisions,
alternatives and limits; [procedure](../../development/sync-recovery.md) records handoff.

| Requirement | Implementation and synthetic evidence |
| --- | --- |
| Incomplete source protection | Existing planner guards retained; executor tests deny partial, revoked and locally cached source deletion. Corrupt/missing state never becomes empty authoritative input. |
| Mass deletion | Default-deny exact whole-plan approval checked repeatedly; permissive item authority cannot bypass it and changed deletion sets invalidate approval. |
| Destination reconstruction | Authenticated lease-bound restoration; default standby; lost creation response requires original intent, candidate ID and verified empty inventory, without another POST. |
| Missing mappings | Retained snapshot import into empty store preserves IDs/history and promotes prepared to unknown; full remote inventory rejects partial backups; original store remains intact. |
| Source migration / legacy baseline | Exact full mapping review and remote content/ETag/creation checks before atomic snapshot CAS; legacy content-v1 independently checked before v2 adoption. Remote edit, stale snapshot and injected commit failure leave metadata unchanged. |
| One active writer / standby | Cooperative generation checks before writes, conditional handoff after draining journal; old/restarted writers, concurrent transfer and uncertain writes denied. Lost handoff response leaves old session standby. |
| Crash/restart recovery | Fresh client and reopened store verify lost writes using original IDs; original prepared intent resumes once after fresh review. No blind unknown replay or false completed checkpoint. |
