## Scope and contracts

- SwiftUI app/navigation, menu-bar presence, preferences/connections shells and a
  cohesive native design system with light/dark, keyboard and accessibility behavior.
- Explicit application composition owns PolicyAuthority. Views consume presentation
  state and trusted application actions; no transport/client receives the authority.
  Avoid global mutable singletons and a catch-all view model.
- Model disabled, denied, revoked, unavailable and unconfigured states honestly.
  Mock selections/grants use CoreDomain/PermissionEngine without OS prompts or
  falsely reporting a live service connected. New connections remain disabled.
- Trusted policy changes invalidate sessions; refresh displayed decisions with a
  new binding under current context. Preview a policy decision distinctly from
  actual local write approval or provider success.
- Specify closing-window versus quitting behavior. Login registration/background
  sync remain explicit opt-in work in the later lifecycle package; no automatic setup.

## Exclusions and acceptance

No EventKit/TCC, OAuth, Keychain, Google/MCP, persistence, scheduling, real accounts,
provider mutations or trusted approval token engine. No speculative entitlements.
Do not relabel an empty mock as a successfully connected account.

Acceptance: native mock navigation and composition work, denied/revoked states are
clear, keyboard/accessibility/light-dark behavior is checked, and all standard
checks pass. Add meaningful composition/safety tests; do not add property-mirroring
UI tests or claim provider behavior from screenshots. Record visual/runtime evidence
separately from builds and tests, using synthetic data only.
