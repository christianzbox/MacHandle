Implement independent EventKit Reminders authorization, list discovery/selection, bounded search
and detail reads, explicit policy projections and MCP read integration. Calendar access, Google
synchronization or a saved preference must never imply Reminders permission. Start disabled and
request OS access only on user opt-in. Keep EventKit objects inside the provider; cancel asynchronous
fetches and reject late results after cancellation, revocation or changed selection. Treat unavailable/
partial reads explicitly; never infer destructive authority from absence. Preserve due-date/time-zone,
completion and recurrence meaning without exposing ungranted notes/fields. Use current Apple/MCP
references and synthetic fixtures; use no personal lists without explicit runtime authorization.

Exercise selected-list isolation, cross-account identity, unavailable/denied/revoked access, field
minimization, bounded queries, cancelled/late callbacks, opaque MCP handles and independent Google/
Calendar grants. Keep signed identity/current OS/client activation gates explicit. Native controls may
show truthful synthetic/permission states but cannot manufacture authorization. Mutation tools,
complete/uncomplete and approval integration belong to package 23, not this read package. Notes still
requires package 26's feasibility gate; no reliable Notes integration is promised by Reminders work.

Update affected ADRs, active brief, progress/evidence, roadmap and coordination, and prepare package
23's brief. Stage/review, run the three gates, commit/push one focused branch and open a review PR.
Stop before merge/release or the next package. Carry package 21's owned live-write follow-up forward;
Reminders read work neither clears that gate nor depends on Google setup.
