status/error/preferences, pause/resume and disconnect flow. Google must work independently
of AI/MCP. The maintainer is developing personally, has no organization/D-U-N-S number,
and is not preparing a release yet. Free Apple registration and isolated Google External

scope classification, security-assessment exemption or authority to use real calendars.

Before live activation, prove actual client/account/installation identity, separate stable
credential namespaces, signed sandbox/Keychain behavior and private destination sharing
without broadening scopes. Verify calendar.app.created classification in the actual Google
console. Its permission includes editing/deleting events in app-created calendars; edits
on selected Apple sources update the saved Google event identity in the one-way mirror.
Retain original-calendar read-only access and exact source/resource/field/approval checks.

Compose one canonical store/client/coordinator per destination. Observe the authorized
source change stream and complete workspace/network state; sessionActive AND awake gate
scheduling. No lifecycle hint may grant authority or reuse a stale approved preview.
Pause/drain before transfer; unresolved writes require reviewed recovery. Stop all owned
tasks/observers on shutdown. Resolve initial lifecycle state, locked Keychain and settings
restoration conservatively. Never run source reads or ask OS permissions merely at launch.

Design recovery and confirmation UI around existing immutable reviews and original IDs.
Require full exact destructive-plan approval. If account setup or supported privacy proof
is missing, preserve honest disabled states and record remaining owner/trigger gates;
synthetic UI is not end-to-end provider acceptance. Do not bypass sandbox/privacy checks.

Use isolated synthetic account/calendar fixtures only with explicit live-test authorization.
Demonstrate initial sync, Apple edits updating the existing Google copy, repeat-run
idempotency, privacy clearing, interrupted writes, revocation and writer transfer. Record
local, hosted, signed-device and live Google evidence independently. Update ADRs/brief/
roadmap/progress/coordination and prepare package 17's focused brief. Run all three gates,
commit/push and open one review PR; stop before merge or release.
