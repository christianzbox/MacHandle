Implement typed Reminder create/update, complete/uncomplete and delete proposals with exact local
review and current policy/OS/selection/field checks. Deletion requires explicit acknowledgement.
Treat completion timestamp, due civil/floating/zone components and recurrence-rule effects separately;
completing a recurring reminder must not silently authorize another occurrence or future-series change.
Package 22 reports recurrence presence only and returns unknown revision: add a scoped observed-state
path before permitting mutations. Do not turn read handles, saved grants or caller booleans into approval.

Design durable intent/receipt and uncertain-outcome containment for Reminders; do not reuse a Calendar
journal entry as authority or silently broaden its schema. Verify EventKit save/remove conflict and
completion behavior from current official documentation, and retain honest non-atomic-provider limits.
MCP mutation tools require verified identity/native review and safe proposal binding; keep production
gates closed where signed/runtime setup is unavailable. Use deterministic synthetic providers; actual
runtime writes require explicitly authorized isolated lists. Never touch personal reminders for tests.

Exercise replay/expiry, current authority and target changes, before/after acceptance cancellation,
recurrence/due/completion boundaries, uncertain receipts and restart. Keep Calendar/Google access
independent. Update affected ADRs, acceptance/progress/roadmap/coordination and prepare package 24.
Stage/review, run all three gates, commit/push and open one PR. Stop for review without merge,
auto-merge, release or beginning Contacts/Notes implementation.


## Implementation and acceptance

[ADR-0028](../../architecture/decisions/0028-reminders-management.md) records the design,
alternatives and owned activation/capability limits. [Developer checks](../../development/reminders-management.md)
provide repeatable synthetic/native/protocol checks. Source code is implemented; full check evidence
and exact final head are recorded in progress and the GitHub PR, separately from hosted/live results.

| Requirement | Implementation / evidence | Remaining limit |
| --- | --- | --- |
| Create, update, due, complete/uncomplete, delete | Independent typed operations, six-operation synthetic provider tests, gated EventKit save/remove backend | No live writes; standalone nonrecurring candidates only |
| Exact approval and observed state | Scoped observation permit, server-bound current revision, per-field review, short-lived single-use confirmation, explicit delete acknowledgement | Local observation is not EventKit atomic CAS |
| Independent permissions | Current OS/selection/operation/read/write checks; separate uncomplete grant; Google denial | Saved read candidates never gain writes; live native wiring gated |
| Due/completion/recurrence | Gregorian date-only/floating/named components, DST civil round trips, explicit completion timestamp semantics; recurring targets denied | Recurrence edits/effects, alarms and list moves explicitly deferred with owners/triggers in ADR |
| MCP mutations | propose_reminder_change and commit_reminder_change; native-only confirmation method, no wire approval; schema/subprocess/SDK checks | Standalone helper cannot locally confirm; separate synthetic fixture only |
| Native review | Six sample actions, inert before/after values, deletion checkbox and cancel; model tests | No live-list editor or signed-runtime acceptance claim |
| Durable effects and restart | Dedicated journal identity/schema, durable intent before acceptance, receipt matching, uncertainty blocks restart/replay | Recovery is containment, not auto-reconciliation; finite retention gate |
| Future work | Prepared [package 24 brief](pr-24.md) only | No Contacts/Notes implementation authorized |

No personal content, real Reminder writes, permission prompt, production store, signing identity,
client configuration, global toolchain selection or release change is part of this package.
