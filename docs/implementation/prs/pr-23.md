Implement typed Reminder create/update, complete/uncomplete and delete proposals with exact local
review and current policy/OS/selection/field checks. Deletion requires explicit acknowledgement.
Treat completion timestamp, due civil/floating/zone components and recurrence-rule effects separately;
completing a recurring reminder must not silently authorize another occurrence or future-series change.
Package 22 reports recurrence presence only and returns unknown revision: add a scoped observed-state
path before permitting mutations. Do not turn read handles, saved grants or caller booleans into approval.

Design durable intent/receipt and uncertain-outcome containment for Reminders; do not reuse a Calendar
journal entry as authority or silently broaden its schema. Verify EventKit save/remove conflict and
completion behavior from current official documentation, and retain honest non-atomic-provider limits.
MCP mutation tools require verified identity/native review and safe proposal binding; keep production
gates closed where signed/runtime setup is unavailable. Use deterministic synthetic providers; actual
runtime writes require explicitly authorized isolated lists. Never touch personal reminders for tests.
