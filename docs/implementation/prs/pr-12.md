Implement ordered execution, partial-failure handling, durable operation preparation,
remote success verification, safe retries and conditional checkpoints. The executor
receives source reads only. Never write to original EventKit calendars. A planner
proposal, policy flag, ownership enum, persisted mapping or checkpoint grants no authority.

Design trusted adapters for scope/account binding, field consent, source/destination
freshness/completeness, verified remote ownership and a single current destination writer.
Do not relabel EventKit local-cache reads as authoritative upstream absence or bypass
unresolved destination privacy/signing gates. If evidence cannot be established, remain
blocked and document the owner/trigger. Preserve package 13/14 recurrence/recovery gates.

Persist stable operation/event IDs before dispatch; beginAttempt must commit unknown
before any network call. Bridge those IDs into the internal destination client safely.
Revalidate current permission/selection/policy, expected version, ownership and exact
local confirmation for deletion before dispatch. Unknown writes require verification,
not blind replay/new IDs. Resolve timestamp/timezone canonicalization without silent
loss; plan fingerprints are not remote IDs. Only verified completed reconciliation may
advance checkpoints or be shown as successful. Conflicts stop affected work visibly.

Use synthetic injected source/destination/store failures for interruption, cancellation,
revocation, policy changes, retries and lost responses. Test no duplicate effects, no
source writes and no false success. Live activation still requires separately authorized
account/setup/privacy/signed acceptance. Update brief/roadmap/progress/coordination/ADRs,
run the three gates, prepare package 13's brief and open one PR. Stop before merge.

| Requirement | Implementation / evidence |
| --- | --- |
| Ordered execution | Fresh plan equals preview; stable per-resource order; actor busy guard; synthetic ordering/convergence tests |
| Durable identity | Real SQLite prepare/unknown-before-dispatch; stable IDs bridged to internal Google operations |
| Remote success | Post-write GET verifies markers/content/version; delete verifies absence; atomic result/checkpoint gating |
| Partial failure/retry | Earlier completions retained; no checkpoint on uncertainty; bounded rejection retries recheck authority |
| Interrupted writes | Read-only verification of original unknown insert/update/delete; store/executor reopen without replay |
| Permission boundaries | Internal authority contract, default deny, per-request/commit checks; external activation rejected by compiler |
| Source safety | No Apple provider dependency or writer input; no source mutations or live provider calls in tests |

fifteen compiler rejection probes. Standard staged/final-head gates and hosted status
are recorded in progress and the review PR. No live authority/observation adapter exists;
its required checks remain explicit and cannot be satisfied by UI/caller evidence flags.
The app links but never activates the executor. No new account/key is needed for tests.
