trusted application contracts and policy projections. Preserve exact resource/window/field

## Implementation and acceptance

See [ADR-0023](../../architecture/decisions/0023-mcp-calendar-reads.md) and the
[developer procedure](../../development/mcp-calendar-reads.md).

| Requirement | Implemented evidence | Boundary |
| --- | --- | --- |
| Calendar discovery | Per-resource discover decisions, trusted projection and opaque calendar handles | Only selected/permitted names; source inventory is not authentication |
| Availability | Exact scope, empty provider detail fields, projected blocks and uncertainty | No event/calendar identifiers or content; absence never proves free time |
| Search | Strict arguments, bounded window/rows, projected-title-only matching and explicit truncation | Hidden fields cannot affect matches; missing title data cannot imply no matches |
| Detail reads | Opaque expiring occurrence handle, fresh scoped provider read, explicit fields and missing/unknown status | No stale content cache, raw IDs, revision/series metadata or write capability |
| Policy/revocation | Bound session, current OS checks and delivery revalidation after suspension | Synthetic authority only; caller labels/metadata/handles confer no identity |
| Protocol/lifecycle | Both profiles through actual subprocesses and independent official SDK clients | Fixed synthetic helper only; signed broker/actual desktop clients remain unverified |

One new subprocess case exercises all reads/privacy in both protocol profiles; Python
checks total 23. Two additional external compiler probes bring the boundary total to 22.
