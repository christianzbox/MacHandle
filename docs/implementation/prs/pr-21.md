## Implementation and acceptance

| Requirement | Implementation and scoped evidence | Remaining gate |
| --- | --- | --- |
| Approved EventKit create/update/delete | Internal EventKit backend, exact approved proposal and snapshot, immediate `.thisEvent` save/remove; pinned SDK compilation | Production factory always denies; isolated live effects not exercised |
| Target validation | Full OS access, exact store/source/calendar/item, refreshed item, writability/entity support; pure target/scope rejection tests | Actual provider replacement/TCC/sandbox acceptance |
| Version/conflict detection | Last-modified observation plus exact reviewed snapshot, final revalidation after journal suspension; existing stale-approval tests | EventKit has no atomic CAS and can recreate a concurrently deleted event; conflict policy must be resolved before activation |
| Scope and fields | Patch only approved fields, projected snapshots; reject recurrence/detached/invited/unknown/floating/subsecond/unsupported availability or cross-zone all-day writes | Broader recurrence, time and meeting behavior requires explicit provider evidence |
| Durable dispatch and recovery | Separate installation-bound SQLite journal, committed intent before provider, persisted matching receipt, pending/unknown block after restart, no replay/reset | Recovery UI, safe attribution/retention and live process crash experiments; containment is implemented, automatic resolution is not |
| Cancellation/revocation | Trusted authority closure checked after durable preparation and at backend acceptance; tests distinguish before versus after acceptance | Signed broker/current OS/native review integration |
| Isolation | No writer dependency in app/helper/MCP/sync executor; package-only journal/provider, internal backend; Google policy still source-read-only | No live writable grants or mutation tools enabled |
| Validation/handoff | 16 new synthetic tests, 3 new negative compiler probes; three full gates and exact snapshot recorded in progress/PR | Hosted and live evidence reported separately |

The implementation preserves the requirement to test real modifications with explicitly authorized
synthetic calendars; none has been authorized/configured. Do not equate synthetic backend tests with
EventKit runtime acceptance. No permission prompt, personal content, client configuration or account
was used. See [developer checks](../../development/calendar-mutations.md).
