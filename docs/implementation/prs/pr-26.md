This is a mandatory feasibility/security decision, not permission to ship a Notes integration.
Investigate current supported AppleScript/Automation and Shortcuts APIs, sandbox and distribution
constraints, explicit per-service consent, account/folder/note identity, content fidelity, locked
notes, attachments, search, create/update/delete and conflict/approval boundaries. Distinguish Notes.app
from the restricted notes property of Contacts. No private Apple APIs, internal Notes databases or
permission bypass. Inspect only supported documentation/dictionaries until fixture authorization is
available; do not browse personal notes or trigger Automation/TCC prompts without explicit permission.

Use isolated synthetic fixtures only if authorized. Record each capability as supported with scoped
proof, unsupported with evidence, or unresolved with owner/trigger. Evaluate least-privilege reads,
rich-text/attachment loss, content-as-instructions, hidden/locked content, output minimization,
revocation/cancellation, target continuity and uncertain writes. Do not equate script compilation,
API availability or an unsigned experiment with signed/sandbox/distribution acceptance.

Produce an ADR and capability/decision matrix concluding either a safe narrow package 27 scope or an
explicit reasoned deferral. Prepare package 27 accordingly; do not implement it. Keep existing Contacts,
Calendar and Reminder live factories closed. Update roadmap/progress/coordination/brief/architecture,
run appropriate checks and all required repository gates, commit/push and open one review PR. Stop;
no merge, auto-merge, publication or implicit personal Notes access.

## Implementation and acceptance

[ADR-0031](../../architecture/decisions/0031-notes-feasibility.md) defers live Notes activation on
insufficient runtime proof. The [evidence/matrix](../../development/notes-feasibility.md) records
official source research and a version/hash-bound inspection of shipped public dictionaries,
including inherited Standard commands and access groups. It distinguishes declared API surface
from safe reads/writes, signed sandbox behavior and distribution acceptance.

| Requirement | Evidence / remaining gate |
| --- | --- |
| Supported approaches and sandbox/consent | Apple events, user-installed AppleScript and Shortcuts compared; no permissions or runtime configuration changed |
| Identity, fidelity, locks, shared content, attachments and CRUD | Per-capability matrix records declarations, unknowns, exclusions and reproducible next proof |
| Synthetic sandboxed proof of concept | **Deferred, not performed.** No isolated authorized fixture environment/signing setup exists; user requests preservation of personal iCloud and testing later. Engineering owns G1–G6 once maintainer setup/authorization is available. Offline mocks are not substituted as proof. |
| Security decision | No live capabilities verified; no private API/database, arbitrary script, implicit unlock, unsupported mutation or permission bypass |
| Conditional package 27 | [Focused brief](pr-27.md) prepared for explicit deferral/limitations only; no implementation in this package |
| Repository checks | Required three gates and documentation consistency; exact results in progress and final SHA/hosted checks in the PR. These do not prove Notes feasibility. |

Only documentation changes. Existing application/provider/helper behavior, entitlements and permission
strings remain unchanged. No Notes app launch, Apple events, Shortcuts enumeration/execution, personal
data, account setting or private database access is part of this review. The decision deliverable is
ready for review; the original runtime-proof requirement remains an owned deferred acceptance item.
