## In Scope
Resource/connection identities; calendar/event/occurrence and availability types;
reminder and contact representations; proposed-operation types; explicit provider
errors and operation results. Model domain differences rather than generic blobs.
Create a cohesive CoreDomain package only now, with deterministic unit tests.

## Out of Scope
Policy engine implementation, Apple providers/permissions, network/authentication,
SQLite implementation, sync planning, MCP transport, and UI development.

## Contracts
No SwiftUI, EventKit, Google JSON, transport objects, or SQLite imports in domain.
Separate read vs write contracts. Preserve recurrence/timezone identity needs from
ADRs; do not assume mutable start times uniquely identify occurrences.

## Security
Keep identities typed and connection scope explicit. A domain value cannot itself
grant permission. Data text must remain inert. Use synthetic data and avoid logging
content or collecting unneeded contact fields in the model.

## Implementation Notes
Prefer the smallest model surface justified by upcoming PRs. Do not build a giant
universal resource object or speculative provider framework. Document equality,
identity stability, completeness, time-boundary semantics, and failure distinctions.

## Tests
Deterministic identity/equality, invalid intervals, all-day/timezone representations,
completeness/error distinctions, and type boundaries using synthetic fixtures.
Run full existing checks; do not claim real-provider semantics from model tests.

## Acceptance Criteria
Models compile without infrastructure/UI dependencies; invariants have meaningful
tests; PR-04 can express resource-specific policy with the chosen types.

## Documentation
Update architecture, progress, coordination, roadmap, relevant ADRs, testing, and create
PR-04's focused policy-engine brief with concrete contracts.

## Handoff
Open a focused PR and stop for review. List contracts and cases that policy tests
must cover, especially cross-connection isolation, field filtering, and revocation.

## Constraints established by PR-02

Read [ADR-0004](../../architecture/decisions/0004-platform-and-apple-apis.md),
[ADR-0005](../../architecture/decisions/0005-google-desktop-boundary.md),
[ADR-0006](../../architecture/decisions/0006-local-mcp-and-processes.md) and
[ADR-0007](../../architecture/decisions/0007-lifecycle-identity-and-distribution.md).
These are researched API/design constraints, not live provider guarantees.
The implementation baseline is macOS 14 / Swift 6 with the existing pinned tools.

- Separate app connection identity, provider/account/resource reference and opaque
  credential handle. Neither a string ID, protocol metadata nor an OS grant confers
  authority. Keep disabled/revoked/unsupported/denied states expressible and separate
  from field/operation policy; no policy engine or transport session in PR-03.
- Calendar/read and mutation contracts are distinct. Sync cannot be injected with
  a source writer. Discovery failure cannot become an empty selected-calendar set
  meaning "all". Express observation coverage (resources, time window, pagination/
  completeness and failure) separately from items; unknown freshness is not complete
  upstream state. Empty, missing, unavailable and denied are distinct outcomes.
- Namespace provider identifiers; EventKit local IDs can change on full resync,
  external IDs can duplicate, and Contacts IDs are device-local. Model unresolved
  or ambiguous references rather than silently equating records by display name.
  Avoid claiming cross-Mac identity or a provider revision where none is available.
- Preserve original recurrence anchor separately from mutable event start/end and
  provider series/item references. Represent timed intervals and all-day local dates
  with explicit timezone/calendar semantics; define exclusive ends and valid ranges.
  Keep coverage horizon separate from identity. Do not implement recurrence expansion
  or select a final matching algorithm before PR-07/13 provider experiments.
- Reminder due date components (possibly date-only/timezone-unspecified) differ from
  an alarm and completion instant. Do not encode all reminder dates as UTC instants.
- Contacts expose explicit typed fields and distinguish not fetched/not authorized
  from fetched-empty. Unified and underlying record references must not be conflated.
  No native macOS limited-authorization assumption or automatic whole-contact export.
- Proposed mutations carry exact typed changes, target and requesting connection,
  with precondition/version evidence and explicit conflict/unknown outcomes. A
  proposal is not an approval. Leave signing, token issuance/consumption and policy
  generation enforcement to PR-04/19/20; no serializable "approved" flag granting power.
- Represent destination reference/ownership separately from its display name and
  OAuth scope. Lost mapping, incomplete snapshot or unknown ownership requires
  recovery, never automatic selection/deletion. Preserve opaque observed revision
  evidence and an unknown mutation outcome so adapters can distinguish a conflict
  from a potentially completed write. Keep Google wire JSON/HTTP status codes outside
  domain; implementation and retry policy remain PR-09/12.

Acceptance tests should exercise the meaningful distinctions above: invalid/time
boundaries, moved-occurrence identity, namespace collisions, incomplete versus empty
snapshots, unfetched versus empty fields, date-only reminder values, and inability
to supply write capability through the read contract. Use small synthetic fixtures;
avoid mirroring every stored property with a trivial getter test. Document what a
model cannot prove about provider freshness, atomicity or cross-device stability.

Final production bundle allocation, Google privacy/consent, external-helper IPC,
actual pairing and signed/oldest-OS runtime evidence remain owned by their later PRs.
PR-03 must preserve these uncertainty states, not resolve them with guessed constants,
add entitlements, connect services or implement a transport. PR-02 merge and user
authorization are verified above; PR-04 still requires its own merge/authorization gate.


## Implementation and acceptance map

Implemented for review, not merged. [ADR-0008](../../architecture/decisions/0008-core-domain-contracts.md)
records the chosen contracts, alternatives, constraints and consequences.

| Requirement | Implementation | Scoped evidence |
| --- | --- | --- |
| Typed identities and connections | `Identity.swift`: tagged opaque IDs, provider/store/account namespace, resource references, resolution/connection/OS states | Namespace collision/opaque spelling and disabled-default tests; compiler rejects ConnectionID as EventID |
| Calendar/events/availability | `Calendar.swift`: resource, occurrence/original anchor, explicit selection, snapshots and detail-free availability blocks | Moved occurrence retains anchor, unknown differs from nonrecurring, other-calendar/outside-window rejection, spanning events retained, availability bounded |
| Time semantics | `Time.swift`: finite Instant, nonempty half-open ranges, Gregorian civil dates/exclusive end, timezone IDs, wall-clock components | Invalid/adjacent/reversed interval checks, leap-year/date rejection, all-day DST-date representation and floating due distinctions; no DST expansion proof |
| Reminders | `Reminder.swift`: scoped identity, fetched-field states, due separate from completion | Date-only/floating/zoned distinction, completion without timestamp, due-change/complete operation separation |
| Contacts | `Contact.swift`: explicit typed fields, unified vs underlying references, optional fetched linked records | Unfetched/unauthorized/fetched-empty distinctions; same raw ID does not equate unified/underlying records; compiler rejects unified deletion target |
| Completeness and errors | `Observation.swift`: observation state, pagination/interruption/unknown, freshness, provider failure and mutation results | Empty/partial/unknown/failed/cached cases remain distinguishable; unknown mutation outcome is separate from conflict/failure |
| Exact proposals | `Operations.swift`: typed resource mutations, nonempty patches, explicit clear vs unchanged, target/revision/connection/operation binding | Patch rejection/clear-field scope, mutation operation mapping, proposal inequality when connection/target/payload/precondition changes |
| Independent domain and source reads | One `CoreDomain` product/target; no target dependencies or infrastructure imports; separate async read/write contracts | Dependency/import guard, positive compiler control, rejection of `apply` through CalendarReading; async synthetic reader requires no writer implementation |

Source files are under `Sources/CoreDomain`; public-API tests are in
`Tests/CoreDomainTests/DomainTests.swift`. No runtime dependency, provider, entitlement,
transport, database, UI or approval issuer is introduced. No Codable format or durable
fingerprint is implied by Hashable. Actual input boundary codecs must validate values.

Full staged and exact final-head checks use the three standard commands. Exact SHA,
results and local/hosted limits are recorded in [progress](../progress.md),
[coordination](../pr-coordination.md) and the PR. The focused 18 domain + 1 foundation
tests and compiler checks passed during implementation; no real provider tests ran.

pure implementation. Broader metadata/series operations and live acceptance remain
