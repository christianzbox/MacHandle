## Scope and gates

Implement an explicit independent Google connect action, desktop browser OAuth with
PKCE and state/redirect validation, Keychain token storage, serialized refresh,
revocation and disconnect. Do not reuse local Calendar read selection/policy as a Google
grant, or enable MCP implicitly. No event writes, destination client, synchronization,
Calendar mutations, database, MCP listener or production release.

Before live credentials, maintainer must confirm/register the production bundle and
Keychain namespace; preserve separate development identities. Recheck current official
Google desktop redirect/consent/scope rules and app-created scope compatibility. Record
console configuration and any required user action without storing credentials. Use
an ephemeral loopback receiver bound locally with validated state/PKCE, one transaction,
timeout/cancel cleanup and no unauthenticated general remote listener. Choose supporting
modules only as needed and record alternatives/entitlements in an ADR.

Keychain access stays in the owning trusted component. No tokens in preferences,
plaintext files, URLs in logs, preview history, diagnostics, Git or cross-Mac handoff.
Locked/unavailable Keychain pauses work; never silently weaken access controls. Test
refresh coalescing, cancellation, stale responses, invalid grants and reauthentication.
Local disconnect must stop this Mac and clear its credentials; explain separately
that remote grant revocation may affect other installations and is not destination
delete or writer transfer. No remote cleanup without its own explicit operation.

## Acceptance and handoff

Use injected browser/HTTP/clock/credential interfaces and synthetic protocol fixtures
for state/PKCE/redirect mismatch, expiry/cancel, callback replay, missing/locked credentials,
refresh races and disconnect/revoke. Verify signed Keychain continuity and isolated
Google account flows only with explicit authorization; synthetic tests are not live
OAuth proof. If identity/console access is unavailable, complete safe injectable work
and document the exact activation blocker, owner and revisit trigger without claiming
working sign-in. Never invent client IDs or production identity decisions.

Run all three staged gates; update this brief, roadmap, progress, coordination and
ADRs with exact local/hosted/live distinctions. Prepare package 09's focused brief,
open one descriptive review PR and stop. Package 07's live Calendar gate remains open
until separately verified; OAuth work does not resolve it.
